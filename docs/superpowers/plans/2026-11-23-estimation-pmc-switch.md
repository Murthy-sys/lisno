# Estimation PMC switch task plan

[Approved specification](../specs/2026-11-23-estimation-pmc-switch-design.md)

1. **Trace the saved configuration.** The backend owner will follow one main line by stable ID from its latest saved revision through Signature catalogue projection and estimate-save validation. Check applicability, base availability, PMC inputs and the calculated vendor rate at 1 sq-ft. Record whether the server permits a pricing-mode change for the draft actor.
2. **Reproduce the switch behavior.** The frontend owner can work in parallel with step 1. Exercise a selected POP false ceiling line in a new draft and a reopened draft. Trace the catalogue response through draft hydration, switch eligibility and the click handler. Distinguish disabled controls from clicks that lose their change. Record the first divergence and whether it was observed on a fixture or the reported estimate.
3. **Correct the confirmed failure.** After both traces, the integration owner will reconcile the evidence and assign the fix to the layer that loses or rejects valid data. Preserve tier and revision identity, server permissions, historical amounts and the established PMC calculation. The frontend owner will surface the actual reason beside an unavailable switch, including catalogue refresh, edit restrictions, missing source or incomplete tier pricing.
4. **Verify the workflow.** On the integrated change, enable PMC with one click at 1 sq-ft, check vendor payable and internal margin against the canonical calculation, save and reopen. Repeat for a new and existing draft. Check a tier with missing settings, a restricted user, a frozen estimate and a refreshing catalogue. Verify the reason is readable by keyboard and on touch screens. Run focused regressions, affected workspace typechecks and builds, and `git diff --check`. Report any limits on reproducing the user's exact record.
