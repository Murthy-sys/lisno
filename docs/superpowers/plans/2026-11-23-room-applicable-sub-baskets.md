# Room-specific Sub-Basket visibility

Implement the [approved display rule](../specs/2026-11-23-room-applicable-sub-baskets-design.md) in the Sales estimate builder.

1. **Capture the baseline.** The integration owner records the dirty paths and inspects existing builder and test diffs. Trace the active room type, catalogue availability, editable rows and incompatible-assignment review before assigning edits.
2. **Filter the rendered groups.** The UI owner edits `frontend/src/features/leads/ConfiguredEstimateBuilder.tsx`. Once catalogue data is available, check regular and temporary lines with the existing room matcher before rendering each Sub-Basket. Use the full group membership independently of search, pagination, default visibility and price. Retain groups needed for editable rows. Room changes and catalogue refreshes should update the display without a removal mutation. Preserve Main Basket selection, loading and error handling.
3. **Exercise the room switch.** The test owner edits `frontend/src/features/leads/ConfiguredEstimateBuilder.test.tsx`. Start with a Bedroom-only POP Gypsum group and a Kitchen-compatible sibling. Switch to Kitchen and assert that the whole POP Gypsum group disappears, including its removal action and empty message. Switch back and assert it returns. Cover mixed, unrestricted, temporary, Add-items-only and truly empty groups. Verify editable rows, incompatible assignment review and room totals across switches. Steps 2 and 3 can run in parallel after step 1 because they own separate files.
4. **Verify the integrated result.** Run the focused builder tests, frontend typecheck and production build. Exercise room switching with the keyboard on desktop and at mobile width. Confirm that refreshing saved room applicability updates the group, hiding it sends no removal request, and search and pagination still work. Inspect the final diff and run `git diff --check`.
