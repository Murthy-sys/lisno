Source of truth: [approved specification](../specs/2026-09-28-mode-quick-summary-tab-progress-design.md).

## Baseline and ownership

- The previous implementation already shows the four saved calculation scopes and derives progress from registered tabs across backend, web, and mobile. Preserve that behavior; this revision extends the saved Mode content in Quick Summary. No backend contract or persisted data change is planned.
- Capture `git status --short` and per-target diffs before writers start. The worktree contains concurrent vendor-induction work and earlier Mode changes. Preserve existing edits; do not stage, revert, or reformat unrelated paths.
- Primary agent owns the shared projection and public row shape, cross-client contract decisions, integration, and final reconciliation. In execution mode A, web and mobile may be separate writers after the shared row shape is settled. Each owns its tests and may not edit shared or the other client. Existing backend progress code remains with the primary agent if a regression fix is needed.

Run focused shared/web/mobile rendered interaction and accessibility tests, relevant typechecks/builds, `git diff --check`, and status. In mode A, request an integrity review after writers and run a verification runner on the integrated worktree. Report exact results and unrun checks. No dependency, migration, seed, commit, deployment, or production write is planned.

## Acceptance and parallel boundaries

- Task 1 fixes the projection contract before tasks 2 and 3 run concurrently on disjoint web and mobile paths. The primary agent retains shared code and regression integration. No backend writer is needed for the clarified Quick Summary scope.
- Acceptance maps to AC1–AC5 in the approved specification: every user-editable saved Mode value appears on both clients, unsaved/generated/internal values do not, independent failures remain visible and retryable, all content is accessible at narrow widths, and registered-tab progress and activation/history invariants remain intact.
