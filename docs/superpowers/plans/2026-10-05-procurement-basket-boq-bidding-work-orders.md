## Delivery boundary

Implement the approved specification end to end under Procurement → Projects. The basket workspace, vendor-neutral BOQ and temporary invitations, bid comparison, award approvals, transactional work-order issuance, and four-tab package monitor must use the approved estimate and existing purchase-order commitment authority. **No Configuration file, API, screen, model, saved record, or calculation is to be changed.** Historical orders and open legacy requests remain accessible. No production send, seed, backfill, migration, deployment, commit, or push is included.

This plan is the sole task-plan artifact for this request. Its acceptance references correspond to the specification's AC1–AC9.

## Verification and acceptance gates

1. **Domain arithmetic and source gate (AC1–AC2, AC5–AC6):** focused backend tests for two rooms with repeated labels, two unequal projects, included/excluded lines, mode low-quantity boundary, missing/digest-mismatched mode, benchmark versus payable separation, partial/full bids, equal-weight score and ties, schedule rounding, exact ₹50,000 gross and one paise above. Reuse saved mode formulas; assert zero Configuration writes.
2. **Security and state gate (AC3–AC7):** route-operation/authorization tests for Procurement, Program Manager, assigned Designer, Finance Manager, Super Admin and vendor-token actor; vendor A cannot see or quote vendor B; expired/superseded/failed links fail; no token in logs/DTO; all four approvals bind to one digest; changes reset votes; existing Super Admin budget override remains additional.
3. **Transactional gate (AC7):** Mongo replica-set tests for simultaneous issue, old individual/project request overlap, source/bid/vendor change during approval, already-issued replay, rollback after PO or assignment failure, finance commitment reconciliation and allocation limit. Check exactly one approved order/revision/assignment per awarded scope and no partial side effect.
4. **Monitor and finance gate (AC8):** order/PDF/portal isolation; planned schedule versus paid amount; invoice/TDS pending without assessment; with an assessment, net/GST/gross and deduction arithmetic reconcile; two unequal projects remain isolated; actual expense/payment joins use stable IDs and do not duplicate project spend.
5. **Rendered UI gate (AC1–AC9):** focused React tests for cards, breadcrumb/back, mode and BOQ edit, vendor search/city unknown, send/bid/counteroffer, comparison/recommendation, award drawer focus trap/return, approval status, issued monitor tabs, legacy history, stale/error/revoked permissions, accessible names and keyboard operation. Browser visual/interaction QA at desktop, tablet, and narrow mobile widths with a realistic multi-basket fixture; inspect console and network errors.
6. **Integrated commands:** focused suites first, then `cd backend && npm run typecheck && npm test && npm run build` and `cd frontend && npm run typecheck && npm test && npm run build`, followed by `git diff --check` and `git status --short`. There is no repository lint script; do not report lint passed. If a suite is blocked by environment, record the exact command, output, and remaining unverified risk.

## Release compatibility and stop conditions

- No live migration/backfill is part of implementation. New nullable fields and indexes need test evidence and an inventory/conflict check. Any later live migration requires separate exact-target authorization, backup, rollback and final dry run.
- The new UI may replace the main project-detail composition only when historical/open legacy requests remain reachable, their Super Admin queue still works, and vendor work/project completion still reads the same approved PO authority.
- The new flow must fail closed if the approved estimate changes, a Configuration digest is unresolved, a bid no longer covers the BOQ, a vendor loses readiness, a required approver is unavailable, or the commitment/allocation fence conflicts. A successful UI state is never fabricated after a failed server mutation.
- A work order is considered issued only after the order commitment, vendor assignment, award status, and audit are durably consistent. PDF and share controls operate only on that issued snapshot.
