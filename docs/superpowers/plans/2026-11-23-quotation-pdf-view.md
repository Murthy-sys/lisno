# View quotation PDFs after save and submission

[Approved specification](../specs/2026-11-23-quotation-pdf-view-design.md)

1. **Confirm the document identity for each action.** Trace both editors from save and submit success to the persisted estimate version, issued revision ID or review round ID. Sales draft access starts with the authorized saved estimate. Client draft access starts with the working quotation returned by the Client quotation service and its customer-visible projection. Sales submission uses the selected issued revision PDF. Client submission uses the authorized review round PDF. Verify what each submit response makes available before binding its button.
2. **Implement saved-draft PDF delivery.** The backend owner will reuse the quotation renderer and enforce the requesting actor's scope, visibility and requested saved version before returning PDF bytes. Identify the document as a draft. Use a protected draft-preview route where the existing contract cannot meet those constraints. Update route authorization and OpenAPI together. Keep submitted downloads bound to their issued artifact. Test version conflicts, incomplete pricing, private fields, hidden items, totals, and access across two projects. Verify preview leaves publication and approval state untouched.
3. **Connect the viewer.** After the request and error contracts are settled, the frontend owner can work in parallel with backend implementation. Reuse existing PDF viewing and authenticated download facilities where available. Add **View quotation PDF** to Sales and Client for a saved draft and a confirmed submission. Bind the action to the last successful save or the exact submission. Identify unsaved edits, keep the editor open until viewing is requested, and give users a return action and download fallback. Clear prior PDF bytes on document changes and discard late responses.
4. **Verify the integrated flows.** Exercise both roles through save, view, edit, failed save and submit. Reopen the submitted document after a later draft edit and check its version and amounts. Verify the draft label, tax-inclusive payable, privacy of internal margins, cross-project denial, and handling of stale or unavailable documents. Test desktop keyboard access, phone-width viewing and return to the editor. Run focused backend and frontend tests, affected workspace typechecks and builds, and `git diff --check`.
