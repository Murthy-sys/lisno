### T7 purchase order vendor index transition

The new PO schema permits multiple orders for one project/vendor and uses the nonunique `project_purchase_order_vendor_list` index. Existing databases may still have the unique `project_purchase_order_vendor_unique` index. Inspect the exact target with `cd backend && MONGODB_URI=<target URI> npx tsx src/migrations/project-purchase-order-vendor-index.ts --database=<target database> --dry-run`. Review the reported index definitions, conflicts, order count, duplicate project/vendor groups, and intended changes before any write. This command was prepared and tested locally; it has not been run on a live database.

Any later live apply needs separate authorization for the named target, a verified full database backup, and an absolute path for a fresh index-metadata snapshot. The gated command is `--database=<target database> --apply --backup-verified --index-metadata=/absolute/path.json`; it writes metadata with exclusive creation before building the nonunique index and dropping only the recognized unique index. A retry after a partial transition is idempotent. To roll back, first inspect again; `--rollback` with the same backup flags recreates the old unique index before dropping the new one only if no project/vendor pair has more than one PO. Once such pairs exist, rollback is unsafe and requires a forward correction rather than deleting orders. Do not run apply or rollback as part of local implementation.
